# Inspector spike

- Install globally from this checkout: `npm install --global .` (run in the repository root). The Inspector spike is not yet published under a separate package name.
- From a project directory, run `inspector` to generate and open a self-contained static HTML snapshot. It discovers Mermaid diagrams and existing test and coverage reports without running tests.
- With the pi-verify Pi extension loaded, `/inspector` runs the bundled Inspector CLI in the session working directory and opens the report. It takes no arguments and requires the package build (`npm run build` for a local checkout).
- The global npm bin directory must be on your `PATH`; check its location with `npm config get prefix`.
- Add `--no-open` to skip opening the browser; `--output path/to/report.html` changes the output location. Paths resolve from the current project directory.
- JUnit discovery checks `junit.xml`, `test-results/junit.xml`, `test-results.xml`, then `reports/junit.xml`; LCOV checks `coverage/lcov.info`, `lcov.info`, then `coverage/lcov/lcov.info`. The first existing file wins independently for each type; discovery is not recursive. The CLI prints the selected paths.
- For Node’s built-in test runner, change the existing `test` command to `node --experimental-test-coverage --test-reporter=spec --test-reporter-destination=stdout --test-reporter=junit --test-reporter-destination=junit.xml --test-reporter=lcov --test-reporter-destination=lcov.info --test <existing test paths>`. Keep any existing build step. This is a one-line `package.json` change; no Inspector wrapper or dependency is needed.
- This repository’s `npm test` uses those native reporters, plus source maps and a source-directory coverage filter. The Pi `test` suite runs `npm test`. Reports are ignored by Git and represent the last run; regenerate them after changes and do not use them after a failed build. Verified with Node 26; other Node versions have not been verified.
- Other test runners can use their own JUnit and LCOV reporters; Inspector only needs those output files. Add `junit.xml`, `lcov.info` (or `coverage/`) and `inspector-report.html` to the consuming project’s `.gitignore`.
- Override either selection with `--junit FILE` or `--lcov FILE`. Missing automatically discovered evidence is shown as unavailable; an invalid discovered report or missing/invalid explicit report fails the command.
- Tests are grouped by file path in an expandable, filterable tree. Project-local absolute paths are made relative to the project root; single-child folder chains share a row. Only folders and files containing failures start expanded. File labels omit `.test` and the extension while preserving earlier suffixes. Cases without paths appear under Unknown location.
- Selecting a test shows its reported result, duration and failure details and, when available, its full source file. A JUnit report may represent only a subset of the suite and may omit file paths or exact test locations.
- LCOV line coverage is shown per file with aggregate line coverage and function/branch counts when provided. Test and coverage source inside the project directory is embedded at generation time; missing or external files have no source view. JavaScript and TypeScript source is highlighted using Shiki; other languages are displayed as plain text. Generated HTML contains project source and report contents; share it only with trusted recipients.
- Coverage files are organized in an expandable, filterable folder tree. Folder percentages combine covered and executable lines across descendant files.
- The **Diagrams** view automatically discovers fenced Mermaid blocks in `.md` and `.markdown` documents under the current project directory, groups cards by document, and uses the nearest preceding heading as the title (or filename and diagram number). Document locations are shown on cards; there are no source controls or diagram counts.
- Discovery includes tracked and untracked documents and respects Git ignores. Without Git, it walks the project directory. Both modes exclude symlinks and generated/dependency directories (`.git`, `node_modules`, `dist`, `build`, `coverage`, `.pi-verify`, `.supercov`). Re-run Inspector to capture document changes.
- Expand a diagram using its icon for a near-fullscreen presentation. Zoom/reset controls live in the popup header; the default and reset fit both dimensions and recalculate on resize. The popup has no document path. Close or Escape restores the preview and focus. Invalid diagrams show a local error without blocking other diagrams; empty projects show guidance.
- Mermaid is bundled locally with strict security settings; no CDN or server is needed. Raw Mermaid definitions are embedded for rendering but not displayed. Custom externally loaded fonts/icon packs are not supplied. The offline renderer increases the HTML size by approximately 3.5 MB.
- This is a spike: no draw.io rendering, documentation reader or CRAP scores. Legacy pi-verify CLI commands remain temporarily available and are not part of Inspector.
- UI is built with Vite and TypeScript into bundled assets, then embedded into the standalone report by the CLI. The report needs no server or network connection. See [Inspector architecture](inspector-architecture.md) for boundaries and verification.
